# 📦 快取策略完整說明

## 🎯 問題：如何判斷要用快取還是抓新資料？

### 答案：**三層判斷機制**

```
1. 用戶手動刷新？ → 忽略快取，抓新資料
2. 快取過期了？   → 抓新資料
3. 快取有效？     → 使用快取
```

---

## 🔄 完整的快取判斷流程

### 流程圖

```
用戶進入頁面
    ↓
檢查是否點擊了刷新按鈕？
    ├─ 是 → 忽略快取，直接請求 API
    └─ 否 ↓
    
檢查快取是否存在？
    ├─ 否 → 請求 API
    └─ 是 ↓
    
檢查快取是否過期（5 分鐘）？
    ├─ 是 → 請求 API
    └─ 否 → 使用快取 ✅
```

## ⏰ 快取有效期設定

### API 響應快取

| 類型 | 有效期 | 原因 |
|------|--------|------|
| Top Tracks | **5 分鐘** | 排行榜變化較慢 |
| Top Artists | **5 分鐘** | 同上 |
| User Profile | **30 分鐘** | 用戶資料很少變化 |
| Playlists | **10 分鐘** | 播放清單可能會編輯 |

### 圖片快取

| 類型 | 有效期 | 原因 |
|------|--------|------|
| 記憶體快取 | **App 運行期間** | 立即存取 |
| 磁碟快取 | **7 天** | 圖片很少變化 |

## 💡 實作細節

### 1. 程式碼邏輯

```swift
// 在 TopView.swift 中

// 步驟 1：檢查是否強制刷新
if !forceRefresh, let cachedData = cache.getData() {
    // 使用快取
    print("✅ 使用快取的數據")
    return cachedData
}

// 步驟 2：從 API 抓取
if forceRefresh {
    print("🔄 強制刷新：忽略快取")
} else {
    print("🌐 快取過期，從 API 載入")
}

// 請求新資料...
```

### 2. 快取過期檢查

```swift
// 在 APIResponseCache.swift 中

private class CacheWrapper<T> {
    let data: T
    let timestamp: Date
    let expirationInterval: TimeInterval
    
    var isExpired: Bool {
        // 計算時間差
        Date().timeIntervalSince(timestamp) > expirationInterval
    }
}
```

### 3. 刷新按鈕動畫

```swift
Image(systemName: "arrow.clockwise")
    .rotationEffect(.degrees(isLoading ? 360 : 0))
    .animation(
        isLoading 
            ? Animation.linear(duration: 1).repeatForever(autoreverses: false) 
            : .default, 
        value: isLoading
    )
```

## 📊 快取策略對比

### 方案 A：不使用快取（優化前）

```
✅ 優點：
- 資料永遠是最新的
- 實作簡單

❌ 缺點：
- 每次都要等待 API 請求（1-2 秒）
- 浪費網路流量
- 耗電
- 使用體驗差
```

### 方案 B：永久快取（不推薦）

```
✅ 優點：
- 超快速度
- 省流量

❌ 缺點：
- 資料永遠不會更新
- 用戶看不到最新內容
```

### 方案 C：時間過期 + 手動刷新（我們的方案）✅

```
✅ 優點：
- 平衡速度和新鮮度
- 5 分鐘內使用快取（瞬間顯示）
- 5 分鐘後自動更新
- 用戶可以手動刷新
- 省流量，不浪費電

❌ 缺點：
- 實作較複雜（但我們已經做好了！）
```

```bash
   Console: ✅ 使用快取的 Tracks 數據
```


### 測試 3：圖片快取

```bash
1. 瀏覽列表，等待圖片載入完成

2. 完全關閉 App

3. 重新啟動 App

4. 圖片立即顯示（從磁碟快取載入）
   （即使過了 1 小時、1 天也會顯示）
   
5. 7 天後：過期圖片會被自動清理
```

## 🔧 進階設定

### 調整快取有效期

在 `APIResponseCache.swift` 中：

```swift
// 想要更頻繁更新（例如 2 分鐘）
private let defaultExpirationInterval: TimeInterval = 2 * 60

// 想要更少更新（例如 10 分鐘）
private let defaultExpirationInterval: TimeInterval = 10 * 60

// 想要更長快取（例如 1 小時）
private let defaultExpirationInterval: TimeInterval = 60 * 60
```

### 調整圖片快取大小

在 `AsyncImageView.swift` 中：

```swift
// 記憶體快取
memoryCache.countLimit = 200  // 增加到 200 張
memoryCache.totalCostLimit = 1024 * 1024 * 150  // 150MB
```

### 清除特定快取

```swift
// 只清除 Tracks 快取
APIResponseCache.shared.clearTracks()

// 只清除 Artists 快取
APIResponseCache.shared.clearArtists()

// 清除所有圖片
ImageCache.shared.removeAll()
```

## 💡 最佳實踐

### 1. 快取策略選擇

| 資料類型 | 建議策略 | 有效期 |
|----------|---------|--------|
| 靜態內容（圖片、圖示） | 長期快取 | 7-30 天 |
| 用戶資料（排行榜） | 短期快取 | 5-10 分鐘 |
| 即時資料（正在播放） | 不快取或極短 | 10-30 秒 |
| 個人資料 | 中期快取 | 30-60 分鐘 |

### 2. 快取清理時機

- ✅ App 啟動時清理過期項目
- ✅ 記憶體警告時清理全部
- ✅ 用戶登出時清理全部
- ✅ 定期後台清理（每 7 天）

### 3. 用戶體驗

- ✅ 載入時顯示動畫（用戶知道在做什麼）
- ✅ 使用快取時瞬間顯示（感覺很快）
- ✅ 提供手動刷新（給用戶控制權）
- ✅ 不要過度快取（保持資料新鮮）
